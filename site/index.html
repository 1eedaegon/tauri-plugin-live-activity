tauri-plugin-live-activity

iOS Live Activities and Android Live Updates for Tauri 2.

GitHub crates.io npm docs.rs 한국어

Is there a Tauri plugin for iOS Live Activities? Yes: tauri-plugin-live-activity. A Tauri 2 app with it starts, updates and ends ActivityKit Live Activities on iOS 16.1 and later, on the Lock Screen and in the Dynamic Island, and shows the same request on Android as a Live Update or an ongoing notification. You describe the layout in TSX, TypeScript or Rust; the plugin draws it, through the liveactivity-rs bridge.

Install

In the folder of your Tauri 2 app:

cargo add tauri-plugin-live-activity --manifest-path src-tauri/Cargo.toml
npm i tauri-plugin-live-activity
npx tauri-plugin-live-activity setup

Then register the plugin in src-tauri/src/lib.rs with .plugin(tauri_plugin_live_activity::init()). setup grants the plugin's permissions, raises the Android minimum to API 26 and, on a Mac, adds the widget extension that draws the activity to the Xcode project. Run it after tauri ios init, and again whenever src-tauri/gen/apple is made from scratch.

A layout in TSX

/** @jsxImportSource tauri-plugin-live-activity/jsx */
import { HStack, Progress, SFSymbol, Text, VStack } from 'tauri-plugin-live-activity/jsx';

// iOS draws this tree on the Lock Screen and in the expanded Dynamic Island;
// Android takes the Texts as title and body and the Progress as its bar.
export const lockScreen = (
  <VStack alignment="leading" spacing={8}>
    <HStack spacing={8}><SFSymbol name="cat.fill" /><Text bind="title" /></HStack>
    <Text bind="status" />
    <Progress bind="done" />
  </VStack>
);

React's useLiveActivity, plain TypeScript and Rust do the same: the README and the usage guide show each.

Supported versions

In short: iOS 16.1+ and Android 8+, and no activities on desktop.

The plugin needs Tauri 2 and Rust 1.90 or later. The floor of every feature is in OS compatibility.

How it works

The plugin is the Tauri side of four crates. It keeps Tauri's commands, events, permissions and the setup command. The liveactivity-rs bridge, the liveactivity crate, holds the request contract, its checks and the lifecycle, and runs each request on the platform's backend:

your Tauri 2 app             a layout in TSX, TypeScript or Rust
  │  start · update · end · events
  ▼
tauri-plugin-live-activity   Tauri commands, events, permissions, setup
  │
  ▼
liveactivity                 the liveactivity-rs bridge: one request contract,
  │                          its checks, the lifecycle
  ├─ iOS 16.1+ ────────────► activitykit (activitykit-rs)
  │                          ActivityKit through its Swift bridge, drawn by the
  │                          app's widget extension: Lock Screen, Dynamic Island
  └─ Android 8.0+ ─────────► liveupdate (liveupdate-rs)
                             an ongoing notification, a Live Update on Android 16+

Questions

Is there a Tauri plugin for iOS Live Activities and the Dynamic Island?

Yes: tauri-plugin-live-activity. It is a community plugin; Tauri has no official one. With it a Tauri 2 app starts, updates and ends ActivityKit Live Activities on iOS 16.1 and later, drawn on the Lock Screen and in the Dynamic Island.

Do I have to add a Widget Extension in Xcode by hand?

No. npx tauri-plugin-live-activity setup adds the widget extension that draws the activity to the Xcode project in src-tauri/gen/apple. Run it again whenever gen/apple is made from scratch.

Does it support Android Live Updates?

Yes. On Android 16 (API 36) and later the plugin asks for a promoted Live Update where the system and the person's settings allow one; elsewhere, from Android 8.0 (API 26), the same request shows as an ongoing notification.

What are the minimum iOS and Android versions?

iOS 16.1 on an iPhone, iPadOS 17 on an iPad and Android 8.0 (API 26). Some features need more: see Supported versions.

Do I have to write Swift or Kotlin?

No. Layouts are TSX, TypeScript or Rust, and the native code comes with the plugin and its crates. A view of your own can still be SwiftUI.

What is liveactivity-rs?

The Rust bridge this plugin is built on, the liveactivity crate. It owns the request contract and the lifecycle, and runs iOS on activitykit-rs and Android on liveupdate-rs.

How is it different from a home-screen widget plugin?

Widget plugins such as tauri-plugin-widgets draw WidgetKit and Android Glance widgets that stay on the home screen. This plugin draws Live Activities and Android Live Updates, which follow one task while it runs. An app can use both.

Can a server update an activity?

On iOS, through APNs: push tokens, push-to-start from iOS 17.2 and broadcast channels from iOS 18. Android has no push path; the app updates its notification.

Does it work on macOS, Windows or Linux?

No. There the activity commands answer UNSUPPORTED_PLATFORM, and getCapabilities() says so.
